Checkout, Order Placement & Admin Flow UML

Diagrams covering customer checkout (/checkout), order placement, order confirmation, and admin dashboard order lifecycle (fetch, status changes, deletion). Payment is currently Cash on Delivery; diagram includes future online payment gateway placeholder.

Key Technologies

Next.js App Router React Client Components Supabase (orders table) localStorage Fallback Cash on Delivery (COD) Admin Dashboard Order Status Workflow Validation Logic

Core Functions & Responsibilities

loadCart()

Hydrate checkout with existing cart; redirect if empty.

validateForm()

Ensure required name/phone/address fields valid.

placeOrder()

Compose order payload, insert into Supabase or fallback to localStorage; clear cart & redirect.

OrderConfirmation.fetchOrder()

Lookup order by id (DB, then local, then mock).

Dashboard.fetchOrders()

Admin load orders (DB first, fallback local).

Dashboard.handleStatusChange()

Update status in DB or local fallback.

Dashboard.handleDeleteOrder()

Delete order (DB or local).

Future: processOnlinePayment()

External gateway auth & callback (placeholder).

Order Data Model

{
  id: string, // Supabase generated UUID or fallback timestamp
  customer_name: string,
  customer_phone: string,
  customer_address: string,
  delivery_instructions: string,
  payment_method: string, // Cash on Delivery (current)
  total_amount: number,
  items: CartItem[],
  order_date: string, // ISO timestamp
  status: string // pending | confirmed | processing | shipped | delivered | cancelled
}

Lifecycle Summary

  1. Pre-Checkout: Cart built via add-to-cart (see separate diagram).
  2. Checkout Load: Validate cart existence; redirect if empty.
  3. User Input & Validation: Form fields validated client-side.
  4. Order Insert: Attempt DB write; fallback to local for reliability demo.
  5. Confirmation: Retrieval hierarchy DB → local → mock.
  6. Admin Management: Fetch orders with same DB-first pattern; status transitions and deletions mirrored to fallback on failure.
  7. Future Gateway: Add payment intent + asynchronous confirmation before DB insert finalize.

Potential Enhancements

  • Replace local fallback with queue + retry worker.
  • Add payment integration (Stripe/PayFast) with webhooks to update status to confirmed.
  • Introduce authentication & role-based access for admin.
  • Server Actions / API Routes for secure order creation instead of direct client insert.
  • Add optimistic UI & toast notifications; remove blocking alerts.
  • Persist order events (status history) in separate table.
