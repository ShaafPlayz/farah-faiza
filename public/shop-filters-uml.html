Filter Components & Functions

Category Filter

Hero chips and sidebar buttons for filtering by product category (All, Dresses, Tops, Bottoms).

Sort Functionality

Dropdown to sort by newest, price (low/high), and popularity with custom comparison logic.

Mobile Filter Toggle

Collapsible sidebar with backdrop overlay for mobile responsive filtering experience.

Size Filter (UI Only)

Visual size selection grid (XS, S, M, L, XL) - currently display-only component.

Product Count Display

Dynamic counter showing filtered results with proper pluralization.

No Results State

Empty state display when filters yield no matching products.

Core Filter Functions

filteredProducts

Logic: products.filter(product => filter === 'all' || product.category.toLowerCase() === filter.toLowerCase())

Purpose: Apply category filtering to product array

Case Insensitive: Uses toLowerCase() for comparison

sortedProducts

Logic: [...filteredProducts].sort((a, b) => comparison)

Purpose: Apply sorting to filtered results

Immutable: Creates new array to avoid mutation

setFilter(category)

Trigger: Hero chips and sidebar buttons

Effect: Updates filter state, recalculates filtered products

Cascade: Automatically triggers sort recalculation

setSortBy(option)

Trigger: Sort dropdown selection

Options: newest, price-low, price-high, popular

Effect: Re-sorts current filtered products

setFiltersOpen(boolean)

Trigger: Mobile filter toggle button

Effect: Shows/hides overlay sidebar on mobile

Responsive: Only active on screen width < 1024px

Product Count Logic

Display: Showing {sortedProducts.length} product{sortedProducts.length !== 1 && 's'}

Grammar: Proper pluralization handling

Dynamic: Updates with every filter/sort change

Sort Comparison Functions

const sortedProducts = [...filteredProducts].sort((a, b) => { switch (sortBy) { case 'price-low': return a.price - b.price case 'price-high': return b.price - a.price case 'popular': return b.id - a.id // Higher ID = more popular default: // 'newest' return new Date(b.created_at).getTime() - new Date(a.created_at).getTime() } })

Filter Performance Considerations

  1. useMemo for categories: Prevents unnecessary re-renders of category options
  2. Immutable sorting: Uses spread operator to avoid mutating original array
  3. Case-insensitive comparison: toLowerCase() ensures reliable category matching
  4. Efficient re-renders: React state changes trigger only necessary component updates
  5. No network requests: All filtering/sorting happens client-side for instant response

Error & Edge Cases

Empty Product Array

Filters gracefully handle empty arrays, showing "No products found" message

No Filter Matches

When category filter yields no results, displays empty state with clear messaging

Invalid Sort Option

Default case in switch statement falls back to 'newest' sort

Missing Product Fields

Date parsing and price comparison handle undefined/null values gracefully
